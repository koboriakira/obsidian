# 日次記録サマリー → dailynote 生成

Obsidian Vault から指定日のセッション記録を収集し、プロジェクト別に構造化した要約を dailynote ディレクトリに生成する。

## Vault パス

```
VAULT=$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/my-vault
```

## ディレクトリ構造

```
dailynote/{YYYY}/{MM}/{DD}/
├── {DATE}.md          ← 既存。Slack Activity Summary等。改変しない
├── screenocr.md       ← analyze-screen-ocr スキルが生成（別スキル）
├── AIセッション.md     ← このスキルが生成（Step 4）
└── summary.md         ← このスキルが生成（Step 5）
```

## 実行手順

### 1. 対象日の決定

引数として対象日（YYYY-MM-DD）を受け取る。省略時は今日の日付（`date +%Y-%m-%d`）を使う。
日付から `{YYYY}`, `{MM}`, `{DD}` を導出する。

### 2. セッション記録の検索

#### 深夜帯の前日帰属ルール

**セッション記録の `created` フィールドが 05:00 未満（00:00〜04:59）の場合、そのセッションは前日の範疇として扱う。**

- 対象日 `{DATE}` のサマリーを生成する際は、翌日（`{DATE+1}`）のファイルも検索し、frontmatter の `created` が `T05:00` より前のものを含める
- 逆に、対象日のファイルでも `created` が `T05:00` 未満のものは「前日のサマリー実行時に処理済み」として扱い、当日サマリーでは除外する

#### 検索コマンド

```bash
# 対象日のファイル（created >= 05:00 のみ対象）
find "$VAULT/Claude" -type f -name "${DATE}*.md"

# 翌日ファイルのうち created < 05:00 のものも含める
NEXT_DATE=$(date -v+1d -j -f "%Y-%m-%d" "$DATE" "+%Y-%m-%d")
find "$VAULT/Claude" -type f -name "${NEXT_DATE}*.md"
# → 読み取り後、frontmatter の created フィールドを確認し T05:00 未満のみ採用
```

セッション記録が1件も見つからない場合は「対象日のセッション記録は見つかりませんでした」と報告して終了する。

### 3. ファイルの読み取りとグルーピング

検出したファイルをすべて読み取り、ディレクトリ構造からプロジェクト別にグルーピングする。

グループのキー:
- `Claude/Code/{org}/{repo}/` → `{repo}`
- `Claude/Chat/` → `Chat`

#### 業務タグの付与

以下に該当するプロジェクトには見出しに `[業務]` タグを付与する:
- `a-kobori` ユーザー配下のリポジトリ
- `spine-lab` 組織配下のリポジトリ

### 4. AIセッション.md の生成

出力先: `$VAULT/dailynote/{YYYY}/{MM}/{DD}/AIセッション.md`（create-or-replace）

ディレクトリが存在しない場合は作成する。

#### フォーマット

```markdown
---
tags:
  - dailynote
  - ai-session
created: {DATE}
---

# AIセッション

## 全体概要

セッション数: N（業務系X件、個人開発Y件、ChatZ件）

（セッション全体の要約を2〜3文で。主要な作業テーマを簡潔にまとめる）

---

### {プロジェクト名} [業務]
セッション数: N

#### [[{DATE}_{トピック名}|{トピック名}]]
- 概要: ...
- 主な成果: ...
- コミット: ...（あれば）
- 残課題: ...（あれば）

---

### {プロジェクト名2}
セッション数: N

#### [[{DATE}_{トピック名}|{トピック名}]]
- 概要: ...
- 主な成果: ...
```

#### Obsidian 内部リンクのルール

各セッションのタイトルには Obsidian 内部リンクを付与する:
- 形式: `[[ファイル名（拡張子なし）|表示名]]`
- ファイル名はセッション記録の実際のファイル名から拡張子を除いたもの
- 表示名はセッションのタイトル（`#` 見出し）

例: ファイル `2026-03-04_対応履歴一括登録機能開発.md` → `[[2026-03-04_対応履歴一括登録機能開発|対応履歴一括登録機能開発（SU-4271）]]`

#### プロジェクトの並び順

1. 業務系プロジェクト（`[業務]` タグ付き）を先に表示
2. 個人開発プロジェクトを後に表示
3. Chat は最後に表示
4. 各グループ内ではセッション数が多い順

### 5. summary.md の生成

出力先: `$VAULT/dailynote/{YYYY}/{MM}/{DD}/summary.md`（create-or-replace）

#### データソース

`$VAULT/dailynote/{YYYY}/{MM}/{DD}/` 配下の全 `.md` ファイルを読み込む。ただし `summary.md` 自身は除外する。

存在しうるファイル:
- `{DATE}.md` — Slack Activity Summary 等（存在しない場合もある）
- `AIセッション.md` — Step 4 で生成したもの
- `screenocr.md` — analyze-screen-ocr スキルが生成（存在しない場合もある）

#### フォーマット

```markdown
---
tags:
  - dailynote
  - summary
created: {DATE}
---

# {DATE} デイリーサマリー

## 一日の概要
（全ソースから3〜5文で要約。業務・個人開発・生活のバランス）

## 業務ハイライト
（Slack + AI業務セッションから主要成果を箇条書き）

## 開発ハイライト
（AI個人開発セッションから技術的成果を箇条書き）

## 行動パターン
（ScreenOCRデータがある場合のみ。操作時間・主要アプリ・集中時間帯）

## 生産性スコア: N / 10
（1行の根拠）
```

#### 条件分岐

- `screenocr.md` が存在しない場合 → 「行動パターン」セクションを省略
- `{DATE}.md`（Slack Activity Summary）がない場合 → 「業務ハイライト」はAIセッションのみから生成

### 6. メモ候補の抽出と保存

サマリー生成後、各セッション記録を横断的に読み直し、以下の観点で「技術記事やブログ、個人メモとして残す価値のあるテーマ」を抽出する:

- **設計判断・設計パターン**: なぜその方式を選んだか、汎用的に応用できる考え方
- **意外な発見・落とし穴**: 知らなければハマる問題とその解決策
- **原則の実例**: DDD、SOLID、冪等性などの原則が実務でどう現れたか
- **ツール・ワークフローの知見**: 開発者の日常を改善する実用的な気づき

抽出対象は **技術的な面白さがあるもの** に限定する。単なる作業記録やルーティン作業は対象外。

#### メモの保存先

```
$VAULT/50_Outputs/00_memo/
```

#### 重複チェック

保存前に `50_Outputs/00_memo/` 配下の既存メモを確認する。

- **類似テーマのメモが既に存在する場合**: 新規作成せず、既存メモのタイトル（`#` 見出し）と本文を更新・追記する。新しい実例や関連セッションを追加し、内容を充実させる
- **類似テーマが存在しない場合**: 新規メモを作成する

#### メモのフォーマット

```markdown
---
created: {DATE}
source: {DATE} 日次記録サマリー
tags:
  - memo
  - {関連タグ}
---

# タイトル — サブタイトル（キャッチーな一言）

## 着想

（何がきっかけで気づいたか、1〜2文）

## 本文

（考え方・パターン・原則の説明。具体例を含む）

## なぜ面白いか / 応用先

（他の場面でも使える理由や展開の可能性）

## 関連セッション

- [[{DATE}_{トピック名}]]
```

#### 保存数

0件〜任意の数。無理に抽出しない。該当なしなら何も保存しない。

### 7. Slack 通知

結果を Slack チャンネル `C0AK65QRNMC` に通知する。

#### トークンの取得

```bash
source "$HOME/git/obsidian/.env"
# SLACK_BOT_TOKEN が設定されていること
```

#### 通知内容のフォーマット

```
📅 {DATE} 日次記録サマリー完了

📂 セッション数: N件（業務X件・個人開発Y件・ChatZ件）

📝 生成ファイル:
- AIセッション.md
- summary.md

💡 メモ候補（あれば）:
- {タイトル1}
- {タイトル2}
（メモが0件の場合はこのセクションを省略）
```

#### API 呼び出し

```bash
curl -s -X POST https://slack.com/api/chat.postMessage \
  -H "Authorization: Bearer $SLACK_BOT_TOKEN" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d "{\"channel\": \"C0AK65QRNMC\", \"text\": \"<通知テキスト>\"}"
```

通知に失敗した場合はエラーを報告するが、スキル全体の成否には影響させない。

### 8. 結果の報告

生成したファイルのパスと、収集したセッション数を報告する。メモを保存した場合はそのタイトルとパスも報告する。Slack 通知の成否も合わせて報告する。

## 制約

- ファイルの内容を改変・解釈しない。記録されている事実をそのまま要約する
- 感情や意図の推測はしない
- 数値データ（テスト数、ビルド番号、スコアなど）は正確に転記する
- 既存の `{DATE}.md` は **絶対に改変しない**
