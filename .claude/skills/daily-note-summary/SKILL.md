# 日次記録サマリー → dailynote 追記

Obsidian Vault から指定日のセッション記録を収集し、プロジェクト別に構造化した要約を dailynote に追記する。

## Vault パス

```
VAULT=$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/my-vault
```

## 実行手順

### 1. 対象日の決定

引数として対象日（YYYY-MM-DD）を受け取る。省略時は今日の日付（`date +%Y-%m-%d`）を使う。

### 2. セッション記録の検索

`Claude/` ディレクトリ配下全体から、ファイル名が対象日で始まる `.md` ファイルを検索する。

```bash
find "$VAULT/Claude" -type f -name "${DATE}*.md"
```

### 3. ファイルの読み取りとグルーピング

検出したファイルをすべて読み取り、ディレクトリ構造からプロジェクト別にグルーピングする。

グループのキー:
- `Claude/Code/{org}/{repo}/` → `{repo}`
- `Claude/Chat/` → `Chat`

### 4. 業務タグの付与

以下に該当するプロジェクトには見出しに `[業務]` タグを付与する:
- `a-kobori` ユーザー配下のリポジトリ
- `spine-lab` 組織配下のリポジトリ

### 5. サマリーの生成

以下の形式でサマリーを生成する。`tmp/{DATE}.md` の形式を踏襲すること。

```markdown
## 日次記録サマリー

### 全体概要

セッション数: N（業務系X件、個人開発Y件、ChatZ件）

（セッション全体の要約を2〜3文で。主要な作業テーマを簡潔にまとめる）

---

### {プロジェクト名} [業務]
セッション数: N

#### [[{DATE}_{トピック名}|{トピック名}]]
- 概要: ...
- 主な成果: ...
- コミット: ...（あれば）
- 残課題: ...（あれば）

---

### {プロジェクト名2}
セッション数: N

#### [[{DATE}_{トピック名}|{トピック名}]]
- 概要: ...
- 主な成果: ...
```

#### Obsidian 内部リンクのルール

各セッションのタイトルには Obsidian 内部リンクを付与する:
- 形式: `[[ファイル名（拡張子なし）|表示名]]`
- ファイル名はセッション記録の実際のファイル名から拡張子を除いたもの
- 表示名はセッションのタイトル（`#` 見出し）

例: ファイル `2026-03-04_対応履歴一括登録機能開発.md` → `[[2026-03-04_対応履歴一括登録機能開発|対応履歴一括登録機能開発（SU-4271）]]`

#### プロジェクトの並び順

1. 業務系プロジェクト（`[業務]` タグ付き）を先に表示
2. 個人開発プロジェクトを後に表示
3. Chat は最後に表示
4. 各グループ内ではセッション数が多い順

### 6. dailynote への追記

対象の dailynote ファイル: `$VAULT/dailynote/{DATE}.md`

- ファイルが存在しない場合: 以下のフォーマットで新規作成する

```markdown
---
tags:
  - dailynote
created: {DATE}
---

## 日次記録サマリー

（生成したサマリー）
```

- ファイルが存在する場合:
  - `## 日次記録サマリー` セクションが既に存在する → そのセクション全体を置換（次の `## ` 見出しの直前まで、または EOF まで）
  - `## 日次記録サマリー` セクションが存在しない → ファイル末尾に追記

### 7. メモ候補の抽出と保存

サマリー生成後、各セッション記録を横断的に読み直し、以下の観点で「技術記事やブログ、個人メモとして残す価値のあるテーマ」を抽出する:

- **設計判断・設計パターン**: なぜその方式を選んだか、汎用的に応用できる考え方
- **意外な発見・落とし穴**: 知らなければハマる問題とその解決策
- **原則の実例**: DDD、SOLID、冪等性などの原則が実務でどう現れたか
- **ツール・ワークフローの知見**: 開発者の日常を改善する実用的な気づき

抽出対象は **技術的な面白さがあるもの** に限定する。単なる作業記録やルーティン作業は対象外。

#### メモの保存先

```
$VAULT/50_Outputs/00_memo/
```

#### 重複チェック

保存前に `50_Outputs/00_memo/` 配下の既存メモを確認する。

- **類似テーマのメモが既に存在する場合**: 新規作成せず、既存メモのタイトル（`#` 見出し）と本文を更新・追記する。新しい実例や関連セッションを追加し、内容を充実させる
- **類似テーマが存在しない場合**: 新規メモを作成する

#### メモのフォーマット

```markdown
---
created: {DATE}
source: {DATE} 日次記録サマリー
tags:
  - memo
  - {関連タグ}
---

# タイトル — サブタイトル（キャッチーな一言）

## 着想

（何がきっかけで気づいたか、1〜2文）

## 本文

（考え方・パターン・原則の説明。具体例を含む）

## なぜ面白いか / 応用先

（他の場面でも使える理由や展開の可能性）

## 関連セッション

- [[{DATE}_{トピック名}]]
```

#### 保存数

0件〜任意の数。無理に抽出しない。該当なしなら何も保存しない。

### 8. 結果の報告

追記した dailynote のパスと、収集したセッション数を報告する。メモを保存した場合はそのタイトルとパスも報告する。

## 制約

- ファイルの内容を改変・解釈しない。記録されている事実をそのまま要約する
- 感情や意図の推測はしない
- 数値データ（テスト数、ビルド番号、スコアなど）は正確に転記する
- セッション記録が1件も見つからない場合は、dailynote への追記は行わず「対象日のセッション記録は見つかりませんでした」と報告する
