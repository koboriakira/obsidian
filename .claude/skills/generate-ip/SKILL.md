# generate-ip — IP生成スキル

既存のノート（調査メモ・議事録・ナレッジなど）を読み込み、**再利用可能な知識の塊（IP）** として新しいノートに蒸留する。

> **整理 = ファイルの移動 ではなく 整理 = 新しいIPの作成**

## IPとは

Intermediate Packet（中間成果物）。バラバラな情報から「再利用できる知識の塊」を生成したもの。

- 1IPにつき1概念・1結論
- 元ファイルへのバックリンクを保持する（元ファイルは削除しない）
- タイトルは「〇〇は〇〇である」「〇〇するには〇〇する」のような命題型が望ましい

## 手順

### Step 1: ソースファイルを読む

引数で受け取ったパスまたはノート名でファイルを読む。

```bash
VAULT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/my-vault"
# パス指定の場合: cat "$VAULT/<path>"
# ノート名指定の場合: obsidian read file="<name>" または grep で検索
```

ファイルが見つからない場合は、Vault全体をファイル名で検索して候補を提示する。

### Step 2: IPを設計する

ソースを読んで以下を判断する：

1. **このファイルから抽出できるIPは何か？**
   - 1ファイルから複数IPが抽出できることもある
   - 「ただの記録」であればIPは生成しない（判断して報告）

2. **IP候補ごとに以下を決める：**
   - `concept`: 何についての知識か（10〜20字）
   - `title`: 命題型タイトル（例: 「Aは Bである」「CにはDを使う」）
   - `tags`: 検索・分類用タグ（3〜5個）
   - `body`: 結論→理由→判断基準の順で150〜300字

### Step 3: IPを生成する

**保存先:** `30_Resources/IP/<タイトル>.md`

```markdown
---
type: ip
concept: （概念名）
tags:
  - タグ1
  - タグ2
sources:
  - "[[元ノート名]]"
created: YYYY-MM-DD
uid: （uuidgen コマンドで生成）
---

# タイトル（命題型）

（結論を1文で）

（理由・背景を1〜2文で）

**判断ルール:**
- （この知識をいつ使うか・使わないかを箇条書きで）
```

UIDの生成:
```bash
uuidgen | tr '[:upper:]' '[:lower:]'
```

### Step 4: 完了報告

- 生成したIPのタイトルとパスを報告する
- 「このソースから他にIPが抽出できそう」な場合は提案する
- ソースファイルを削除するかは **ユーザーに確認してから** 行う

## IPを生成すべきでないケース

| ケース | 対応 |
|--------|------|
| タスク・TODO のみ | IPは生成しない。タスク管理に任せる |
| 時事性が高く再利用不可 | IPは生成しない。そのまま保持か削除を提案 |
| 情報が断片的すぎる | IPを生成せず「情報が不足している」と報告 |
| 既存IPと内容が重複する | 既存IPを更新するか統合を提案 |

## 既存IPとの重複チェック

生成前に `30_Resources/IP/` の既存ファイルを確認する。

```bash
ls "$VAULT/30_Resources/IP/" 2>/dev/null
```

概念が重複する場合は新規生成せず、**既存IPの更新または統合**を提案する。
