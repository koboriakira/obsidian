# obsidian-project — Obsidian プロジェクト管理スキル

## プロジェクトフォルダ構成

```
Projects/<プロジェクト名>/
├── _index.md        # エグゼクティブサマリー（常に先頭・常に最新化）
├── tasks/           # タスクディレクトリ（1タスク1ファイル）
│   └── <タスク名>.md
└── ...              # その他のノート（atomic に分割）
```

**プロジェクト開始時に必ず `_index.md` を作成する。タスクは `tasks/` ディレクトリに1ファイル1タスクで管理する（tasks.md は作成しない）。**

### プロジェクト名のフォーマット

チケット（JiraまたはBacklog）が紐づく場合は、必ずチケット番号をprefixとして付ける：

```
{チケット番号}_{プロジェクト名}

例: SU-4452_キッズ大陸写真利益再開後続調査
    COIT_TASK_MANAGEMENT-338_情シス依頼チャンネル構造化
```

- `project:` frontmatterも同じ形式にする
- チケットが紐づかない場合はそのままのプロジェクト名を使う

`_index.md` はアンダースコアプレフィックスによりファイル一覧の先頭に表示される。

## _index.md — エグゼクティブサマリー

### 役割

プロジェクトの「今の状態」をひと目で把握できるファイル。
詳細な調査・議事録・メモは別ファイルに分け、_index.md は**現状の要約のみ**に絞る。

### 更新ルール

**プロジェクトに関する作業を行うたびに _index.md のエグゼクティブサマリーを更新する。**
作業の完了・決定事項・ブロッカーの変化・次のアクションの変化があれば即座に反映する。

### フォーマット

```markdown
---
project: <プロジェクト名>
status: planning | active | on-hold | completed
updated: YYYY-MM-DD
---

# <プロジェクト名>

## 概要

（何のためのプロジェクトか。1〜2文で）

## エグゼクティブサマリー

**ステータス:** Planning / Active / On Hold / Completed

**完了条件:**
- （この条件を満たしたらプロジェクトを completed にして Archives へ移す）

**直近の進捗:**
- （最近完了したこと・決まったこと）

**次のアクション:**
- （次に何をすべきか。具体的に）

**ブロッカー:**
- （なければ「なし」）
```

### ステータスの定義

| ステータス | 意味 |
|-----------|------|
| `planning` | 開始前・検討中 |
| `active` | 進行中 |
| `suspended` | 再開予定日が決まっている一時停止。`resume_date: YYYY-MM-DD` を frontmatter に追加する |
| `on-hold` | 再開目処なしの停止 |
| `completed` | 完了・クローズ |

**`suspended` の運用:**
1. `_index.md` の frontmatter に `resume_date: YYYY-MM-DD` を追記する
2. プロジェクトフォルダを `Archives/` へ移動する
3. `Inbox/YYYY-MM-DD_<プロジェクト名>を再開する.md` を作成してリマインドを残す

## tasks/ — タスクディレクトリ（1タスク1ファイル）

### 役割

プロジェクトのタスクを1ファイル1タスクで管理する。TaskChuteテンプレートに準拠。

### タスクファイルのフォーマット

`tasks/<タスク名>.md` として作成する:

```markdown
---
type: task
uid: <uuid4>
created: YYYY-MM-DDTHH:MM
updated: YYYY-MM-DDTHH:MM
tags: []
scheduled_date: YYYY-MM-DD
section: ""
estimate: 0
start_time: ""
end_time: ""
mode: ""
status: todo
is_routine: false
mit: false
cue: ""
---

（タスクの詳細・背景）

## サブタスク

- [ ] サブタスク名 (分数)
```

### ステータスの定義

| ステータス | 意味 |
|-----------|------|
| `todo` | 未着手 |
| `in_progress` | 作業中 |
| `done` | 完了 |
| `cancelled` | キャンセル |

## プロジェクト化しない判断基準

以下に該当するものは `Projects/` に置かない：

| 種類 | 置き場所 |
|------|---------|
| 「ただやるだけ」で管理の複雑さがないもの（通院・手続き等） | カレンダーや単発タスクで管理 |
| 「いつかやりたい」アイデア（再開時期未定） | `Ref/アイデア/<名前>/` に移動 |
| 継続・定着が目的で終わりのない活動 | プロジェクトをクローズして `Areas/` に移行 |

> プロジェクトは「管理が必要な複雑さ」があるものだけに絞る。

---

## プロジェクトのネスト禁止

**`Projects/` 内のプロジェクトはフラットに保つ。サブフォルダとしてプロジェクトをネストしない。**

あるプロジェクト（例: コンシェルジュ制）から具体的な改善案件が生まれたとき、それをそのプロジェクト内のサブフォルダにしてはいけない。代わりに、`Projects/` の直下に**独立した新規プロジェクト**として作成する。

```
# ❌ やってはいけない（ネスト）
Projects/コンシェルジュ制/
└── FSデスク_集計自動化/   ← サブプロジェクトをネストしない

# ✅ 正しい（フラット）
Projects/コンシェルジュ制/
Projects/FSデスク_集計自動化/   ← 独立したプロジェクトとして切り出す
```

親プロジェクトとの関係は、`_index.md` 内の Obsidian リンクで表現する:

```markdown
## 関連プロジェクト

- [[FSデスク_集計自動化]]（コンシェルジュ制から発生）
```

### なぜフラットにするか

- `Projects/` を開いたとき、進行中の案件が一覧として見渡せる
- 深くネストされたプロジェクトは検索・参照されにくくなる
- プロジェクトは独自のゴール・期限・タスクを持つため、独立して管理した方が明確

## プロジェクト開始チェックリスト

新規プロジェクト作成時は以下の順序で実施する：

- [ ] プロジェクトに関するいまの自分の考えを収集する（ユーザーに確認）
- [ ] 関連するタグ・フォルダを見直す
- [ ] 関連ワードで全フォルダを検索する（`Ref/`・`Inbox/` を優先）
- [ ] 関連メモをプロジェクトフォルダへ移動またはタグづけする
- [ ] 集めたメモの概要を作成し、`_index.md` にプロジェクト計画を立てる

```bash
obsidian search query="<キーワード>" path="Ref"
obsidian search query="<キーワード>" path="Inbox"
```

見つかった場合は「このテンプレート/メモをプロジェクトに持ち込みますか？」と確認する。

## プロジェクトのクローズ基準

以下のいずれかを満たしたらクローズしてよい：

- **完了型**: 完了条件がすべて達成された
- **仕組み整備型**: 「定着・継続」が目的のプロジェクトは、仕組みが整った時点でクローズ。継続運用は `Areas/` または `Inbox/` タスクに引き継ぐ
- **中断型**: 優先度が下がった・環境が変わったなど、完了でなく活動を止める場合

> **原則**: 「定着を待つとプロジェクトが死なない」。習慣化・継続は Areas の仕事であり、Projects の仕事ではない。

---

## プロジェクト完了チェックリスト

プロジェクトを完了・アーカイブするときは以下を順に実施する：

- [ ] `tasks/` ディレクトリの未完了タスクを確認し、引き継ぎ先を明示して完了にする
  - 継続タスク → `Areas/<エリア名>/tasks/` または `Inbox/` に移動
  - 不要なタスク → status: cancelled にしてクローズ理由をメモ
- [ ] `tasks/` の全タスクが done または cancelled になっていることを確認する
- [ ] `_index.md` のステータスを `completed` に更新し、完了条件に ✅ を入れる
- [ ] プロジェクトフォルダ内の IP（中間・最終成果物）を見直し、`Ref/` や `Areas/` に移動する
- [ ] プロジェクトフォルダを `Archives/` へ移動する
- [ ] 活動停止（完了でなく中断）の場合は、アーカイブ前に「現況メモ」をフォルダに添える

## 操作手順

### 新規プロジェクト作成

```bash
# _index.md を作成（tasks/ ディレクトリは最初のタスク作成時に自動生成される）
obsidian create path="Projects/<プロジェクト名>/_index.md" content="..."
# タスクを作成
obsidian create path="Projects/<プロジェクト名>/tasks/<タスク名>.md" content="..."
```

フォルダが存在しない場合は自動作成される。

### _index.md の更新

```bash
obsidian read path="Projects/<プロジェクト名>/_index.md"
# 内容を確認して Write ツールで更新
```

### タスクの追加

```bash
# 新規タスクファイルを作成
obsidian create path="Projects/<プロジェクト名>/tasks/<タスク名>.md" content="..."
```
