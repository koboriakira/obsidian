# obsidian-project — Obsidian プロジェクト管理スキル

## プロジェクトフォルダ構成

```
10_Projects/<プロジェクト名>/
├── _index.md   # エグゼクティブサマリー（常に先頭・常に最新化）
├── tasks.md    # タスク一覧（タスクのみ）
└── ...         # その他のノート（atomic に分割）
```

**プロジェクト開始時に必ず `_index.md` と `tasks.md` を作成する。**

`_index.md` はアンダースコアプレフィックスによりファイル一覧の先頭に表示される。

---

## _index.md — エグゼクティブサマリー

### 役割

プロジェクトの「今の状態」をひと目で把握できるファイル。
詳細な調査・議事録・メモは別ファイルに分け、_index.md は**現状の要約のみ**に絞る。

### 更新ルール

**プロジェクトに関する作業を行うたびに _index.md のエグゼクティブサマリーを更新する。**
作業の完了・決定事項・ブロッカーの変化・次のアクションの変化があれば即座に反映する。

### フォーマット

```markdown
---
project: <プロジェクト名>
status: planning | active | on-hold | completed
updated: YYYY-MM-DD
---

# <プロジェクト名>

## 概要

（何のためのプロジェクトか。1〜2文で）

## エグゼクティブサマリー

**ステータス:** Planning / Active / On Hold / Completed

**完了条件:**
- （この条件を満たしたらプロジェクトを completed にして Archives へ移す）

**直近の進捗:**
- （最近完了したこと・決まったこと）

**次のアクション:**
- （次に何をすべきか。具体的に）

**ブロッカー:**
- （なければ「なし」）
```

### ステータスの定義

| ステータス | 意味 |
|-----------|------|
| `planning` | 開始前・検討中 |
| `active` | 進行中 |
| `on-hold` | 一時停止中 |
| `completed` | 完了 |

---

## tasks.md — タスク一覧

### 役割

プロジェクトのタスクのみを管理する。メモ・調査結果・議事録は別ファイルに分ける。

### フォーマット

```markdown
---
updated: YYYY-MM-DD
---

## 🚧 In Progress

## 📋 Todo

## 🚫 Blocked

## ✅ Done

```

### タスクの記法（/task-board スキル準拠）

| ステータス | 記号 | セクション |
|-----------|------|-----------|
| 未着手 | `[ ]` | 📋 Todo |
| 作業中 | `[/]` | 🚧 In Progress |
| 完了 | `[x]` | ✅ Done |
| ブロック中 | `[-]` | 🚫 Blocked |

```markdown
- [ ] タスク名 ➕ YYYY-MM-DD
- [/] タスク名 🖥 koboriakira ➕ YYYY-MM-DD 🕐 HH:MM
- [x] タスク名 🖥 koboriakira ➕ YYYY-MM-DD 🕐 HH:MM ✅ YYYY-MM-DD
```

## プロジェクトのネスト禁止

**`10_Projects/` 内のプロジェクトはフラットに保つ。サブフォルダとしてプロジェクトをネストしない。**

あるプロジェクト（例: コンシェルジュ制）から具体的な改善案件が生まれたとき、それをそのプロジェクト内のサブフォルダにしてはいけない。代わりに、`10_Projects/` の直下に**独立した新規プロジェクト**として作成する。

```
# ❌ やってはいけない（ネスト）
10_Projects/コンシェルジュ制/
└── FSデスク_集計自動化/   ← サブプロジェクトをネストしない

# ✅ 正しい（フラット）
10_Projects/コンシェルジュ制/
10_Projects/FSデスク_集計自動化/   ← 独立したプロジェクトとして切り出す
```

親プロジェクトとの関係は、`_index.md` や `tasks.md` 内の Obsidian リンクで表現する:

```markdown
## 関連プロジェクト

- [[FSデスク_集計自動化]]（コンシェルジュ制から発生）
```

### なぜフラットにするか

- `10_Projects/` を開いたとき、進行中の案件が一覧として見渡せる
- 深くネストされたプロジェクトは検索・参照されにくくなる
- プロジェクトは独自のゴール・期限・タスクを持つため、独立して管理した方が明確

## プロジェクト開始チェックリスト

新規プロジェクト作成時は以下の順序で実施する：

- [ ] プロジェクトに関するいまの自分の考えを収集する（ユーザーに確認）
- [ ] 関連するタグ・フォルダを見直す
- [ ] 関連ワードで全フォルダを検索する（`30_Resources/`・`00_Inbox/` を優先）
- [ ] 関連メモをプロジェクトフォルダへ移動またはタグづけする
- [ ] 集めたメモの概要を作成し、`_index.md` にプロジェクト計画を立てる

```bash
obsidian search query="<キーワード>" path="30_Resources"
obsidian search query="<キーワード>" path="00_Inbox"
```

見つかった場合は「このテンプレート/メモをプロジェクトに持ち込みますか？」と確認する。

---

## プロジェクト完了チェックリスト

プロジェクトを完了・アーカイブするときは以下を順に実施する：

- [ ] `tasks.md` のタスクをすべて完了にし、タスクボードに記録する
- [ ] `_index.md` のステータスを `completed` に更新し、完了条件に ✅ を入れる
- [ ] プロジェクトフォルダ内の IP（中間・最終成果物）を見直し、`30_Resources/` や `20_Areas/` に移動する
- [ ] プロジェクトフォルダを `40_Archives/` へ移動する
- [ ] 活動停止（完了でなく中断）の場合は、アーカイブ前に「現況メモ」をフォルダに添える

## 操作手順

### 新規プロジェクト作成

```bash
# フォルダ作成
obsidian create path="10_Projects/<プロジェクト名>/_index.md" content="..."
obsidian create path="10_Projects/<プロジェクト名>/tasks.md" content="..."
```

フォルダが存在しない場合は自動作成される。

### _index.md の更新

```bash
obsidian read path="10_Projects/<プロジェクト名>/_index.md"
# 内容を確認して Write ツールで更新
```

### tasks.md へのタスク追加

```bash
obsidian read path="10_Projects/<プロジェクト名>/tasks.md"
# 該当セクションにタスクを追記
```
