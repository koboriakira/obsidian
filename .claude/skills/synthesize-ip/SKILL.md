# synthesize-ip — IPの合成

> IPの定義・フォーマット・保存先ルールは `/ip` スキルを参照すること。

複数の既存IPを組み合わせて、より抽象的・汎用的な知識（第2層IP）を生成する。

## いつ使うか

- 似たテーマのIPが3つ以上溜まったとき
- 「この知識とあの知識、根っこは同じだな」と感じたとき
- ユーザーが「これらをまとめて」と指示したとき
- weekly-review でIPの棚卸しをするとき

## 手順

### Step 1: 合成対象のIPを選ぶ

引数で直接指定されるか、テーマ指定の場合は Wiki/ から関連IPを検索する。

```bash
VAULT="$HOME/obsidian/my-vault"
ls "$VAULT/Wiki/" | grep -i "<テーマ>"
```

最低2つのIPが必要。1つしかない場合は合成ではなく更新を提案する。

### Step 2: 共通パターンを抽出する

対象IPを読み、以下を考える：

1. **これらのIPに共通する上位概念は何か？**
   - 個別の事実ではなく、パターン・原則・フレームワークを見出す
   - 例: 「Auroraはスナップショット経由」+「RDSは暗号化必須」→「AWSデータ保護は制約の事前把握が鍵」

2. **合成IPは元のIPより抽象度が高いか？**
   - 単なる箇条書きのまとめにしない
   - 元IPにはない新しい洞察を含める

### Step 3: 合成IPを生成する

フォーマットは `/ip` スキルの仕様に従う。

`sources` には元のIP名を列挙する：
```yaml
sources:
  - "[[IP名1]]"
  - "[[IP名2]]"
  - "[[IP名3]]"
```

### Step 4: 元IPの処理

元のIPは **削除しない**。合成IPはより抽象的な上位概念であり、元IPの具体的な知識は引き続き有効。

ただし元IPの内容が完全に合成IPに吸収された場合は、元IPの削除をユーザーに提案してよい。

### Step 5: 完了報告

- 合成IPのタイトルとパスを報告する
- 元IPとの関係を簡潔に説明する
- さらに合成できそうなIP群があれば提案する
